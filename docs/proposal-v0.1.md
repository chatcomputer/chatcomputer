# Chat Computer 产品与技术方案

原生 macOS 应用  对话驱动的独立 macOS 虚拟电脑

版本 0.1  |  2026 年 10 月 1 日  |  面向产品定义与工程立项

## 01 产品概述

### 建议结论

建议将 Chat Computer 做成一个原生 Mac 应用：左侧始终展示可接管的 macOS 虚拟桌面，右侧是在宿主机运行的聊天与任务控制台。用户提出目标后，代理在虚拟机里观察、操作、验证，并把文件和完成证据交回用户。首版优先打通“一句话开始，到拿到可用结果”的完整闭环。

技术上以 Apple Virtualization Framework 为底座，优先验证 guest 内的 Cua Driver；宿主机持有模型配置、任务状态与安全策略。先做单虚拟机、单任务、有限应用集。Lume 可以复用为虚拟机管理实现，但嵌入式原生显示与生命周期所有权必须先验证，不能把现有命令行工具直接等同于完整产品。

### 已确认的产品方向

- 应用形态为 macOS 原生客户端，聊天在宿主机，执行发生在独立的 macOS 虚拟机中
- 用户通过自然语言打开网站、使用应用、处理文件，并逐步扩展到持续较久的任务
- 应用内置执行组件与模型配置入口，首次引导后即可使用，不要求用户自己安装开发工具或拼装代理环境
- 暂用 Chat Computer 作为名称；本方案定义产品与技术路径，不代表已经完成实现、性能测试或商用许可确认
### 四项产品原则

结果可验：完成状态必须附结果文件、页面证据或可复查的操作结果。过程可见：用户随时能看见虚拟机正在做什么。边界清楚：代理默认只操作 guest，不获得整个宿主机的控制能力。中断可恢复：暂停、接管、断网和退出都有明确语义，不靠聊天记录猜测进度。

### 当前最重要的立项条件

首先验证嵌入显示、guest 图形会话控制和真实结果交付这三个环节能连成闭环。并行完成 Apple 虚拟化许可、镜像分发和第三方依赖审查。一般商业办公自动化是否落在适用许可范围内尚未解决，不能在上线宣传中默认许可已覆盖。

阅读导航：第 2 节为范围；第 3—4 节为首次体验与交互；第 5—8 节为架构、安全与持久任务；第 9—10 节为验收与实施闸门；第 11 节为演示与待决事项；第 12 节为官方来源。

## 02  首版范围与支持边界

### 优先服务的任务

首批验证围绕个人非商业使用和开发测试场景展开：在公开网站查找资料并保存笔记，整理用户主动导入的文件，在 TextEdit 等基础应用生成可读文件，以及在受控网站执行测试流程。产品长期愿景可以覆盖更广的办公任务，但商业使用边界应在许可审查后确定。

| 能力 | MVP 包含 | 暂不包含 |
| --- | --- | --- |
| 虚拟电脑 | 一个持久 macOS guest；创建、启动、关闭；实时显示与手动接管 | 多虚拟机编排、Windows 或 Linux、远程云桌面 |
| 对话执行 | 单个活动任务；浏览、输入、下载、整理与导出；结果验证 | 任意应用可靠操作、并行争用同一桌面、无人监督高风险交易 |
| 模型 | 一个经过回归测试的视觉与工具调用模型；自带 API Key；用量显示 | 承诺任意兼容端点都可用；本地模型安装与自动调优 |
| 文件与记录 | 显式导入导出；任务事件、产物清单；崩溃后可恢复到待检查状态 | 默认挂载整个主目录、无限屏幕录像、跨设备同步 |
| 持续运行 | 用户在场下的短任务；有限等待、重试、暂停和重启恢复 | 合盖或断电继续运行、全天候无人值守、多用户 SaaS |

### 建议的验证矩阵

Lume 文档的宿主机门槛为 Apple Silicon 与 macOS 13+；Cua Driver 的 macOS 门槛为 14+。它们不是 Chat Computer 的完整兼容承诺。建议产品工程基线从宿主机 macOS 14+ 起，实际发布只列出通过测试的主客系统配对。[S4][S5]

| 项目 | 建议配置或验证方式 |
| --- | --- |
| 硬件 | Apple Silicon；先覆盖较早与较新两代芯片。16 GB 主机内存作为验证起点，24 GB 或以上作为体验推荐候选 |
| 系统配对 | 先验证 macOS 26 主机与同代 guest，再评估 15 与 14；每对锁定实际 build、驱动和模型版本。是否支持跨版本以验证为准 |
| VM 资源 | 初始候选为 4 vCPU、8 GB RAM、80 GB 稀疏磁盘；按 VZ 配置要求及主机余量校验，安装前显示实际空间预算 |
| 应用集 | 首批 Safari、Finder、TextEdit 和受控网页；中文与英文界面均测试。其他应用显示“尚未验证” |

资源数字是待测的产品建议。稀疏磁盘的逻辑容量不等于已用空间；安装介质、升级、下载及备份仍会额外占用宿主磁盘。不要把能开机、能 SSH、能截图或某次演示成功当作整体兼容性证明。

## 03  首次启动与打包交付

### 把复杂步骤做成可恢复的引导

目标是免开发环境配置，不是免系统安装、免登录或免授权。每步应有进度、失败原因、重试与继续入口；中断后从最近完成步骤恢复，不要求用户读终端日志。

1. 检查设备。读取架构、系统版本、可用内存与磁盘；验证恢复镜像和 VZ 配置兼容性。不满足条件时给出具体差额，不启动长时间下载。
2. 选择安装位置与资源。显示 VM、安装介质和备份的预计占用。默认配置可调整，但不能越过 VZ 最小要求。首次先保留足够的宿主机余量。
3. 获取并安装 macOS。引导从 Apple 获取兼容 IPSW，或选择用户已有介质；校验下载完整性，展示适用许可并由用户完成必要接受。分发自有应用和 bootstrap，不默认分发可再分发的完整 macOS 系统镜像。[S1][S3]
4. 建立 guest 用户与桌面。完成必要的系统设置、账户及登录，避免公开默认口令。Apple Account 按任务需要另行登录，首个演示不依赖个人云账户。自动配置可减少操作，但不能代替许可和安全授权。
5. 安装并配对 guest 组件。使用锁定版本、校验来源与签名的驱动和桥接程序。每台 VM 建立独立身份。第一次连接应验证目标 VM，后续禁止悄悄连接到同名的其他机器。
6. 完成 guest 权限。逐项说明辅助功能、屏幕录制及实际工作流触发的自动化或直接捕获权限。用户在 guest 系统界面授权；状态检查后执行截图和无害输入测试。权限被拒绝则停在该步骤，不修改 TCC 数据库，不关闭 SIP。[S5][S7]
7. 配置模型并完成首个任务。在宿主机配置供应商、模型及 Key，说明截图和文本将发往哪里。先检查认证、视觉输入和工具响应，再运行“打开 TextEdit，保存一条测试笔记”，验证文件确实存在并可导出。
### 模型密钥与数据告知

Key 在宿主机 Keychain 保存，聊天记录、任务数据库、guest 磁盘和诊断包均不存明文 Key。输入框支持显示末尾字符、删除和重新验证。Keychain 读取失败时请求用户处理，不降级写入普通配置文件。[S11]

默认不把 Key 传入 guest；由宿主机模型代理发起请求。自定义服务端地址属于高级功能，需显示真实域名、HTTPS 状态和数据流向，禁止用云模型 Key 自动测试未知端点。模型调用应有任务级费用或 token 上限；网络与计费错误要能与桌面控制错误区分。

### 发布物与升级

建议以签名、公证的原生应用交付；内置或按需下载经过验证的辅助组件，保留版本清单与第三方告知。稳定签名关系到 guest 授权身份，升级不能假定 TCC 永久有效。更新在任务安全边界执行，先备份配置，失败可回退组件；系统镜像和模型权重分别审查许可。

## 04  双栏界面与控制权

### 主窗口布局

左侧为实时 guest 桌面，默认约占三分之二宽度；右侧为宿主机聊天与当前任务。分隔条可调，支持桌面放大、聊天折叠及窗口缩放。顶部固定显示 VM 名称、连接状态、当前控制者和暂停按钮；底部显示当前步骤、用量与产物入口。尺寸比例仅作原型起点。

原生显示可用 VZVirtualMachineView 承载，SwiftUI 通过 AppKit 桥接嵌入。它负责 framebuffer 显示及用户键鼠输入，不应被误当作理解 guest UI 的语义自动化接口。[S2]

### 聊天里用户需要看见什么

- 开始前：简短任务目标、预期结果、必要限制，以及需要用户先处理的登录或权限
- 执行中：最近一个有意义的动作和当前等待原因；可展开查看操作记录，不刷屏输出内部推理
- 需要确认时：准确对象、目标网站或收件人、操作内容、影响、相关截图与批准或拒绝按钮
- 完成后：结果摘要、可打开的文件、来源与验证证据；若只有部分完成，列出缺口与下一步
| 状态 | 界面含义 | 允许的后续动作 |
| --- | --- | --- |
| 就绪 | guest、驱动和模型可用 | 输入任务或接管 |
| 执行中 | 代理持有输入权，正在观察或操作 | 暂停、接管、取消 |
| 等待用户 | 需要登录、批准或补充信息 | 用户处理后重新观察；不可自动超时批准 |
| 等待外部 | 下载、页面任务或限流等待 | 显示下次检查或截止条件；可取消 |
| 已暂停 | 不再派发动作；待继续 | 继续时核对桌面变化 |
| 人工接管 | 用户持有键鼠输入权 | 用户明确交还控制权后才恢复 |
| 中断或失败 | 环境丢失或无法可靠确认结果 | 诊断、恢复或结束；不误报完成 |
| 已完成或取消 | 任务终止且日志、产物已落盘 | 查看结果、开启新任务 |

### 暂停 接管与取消必须不同

暂停先撤销调度许可，再停止派发下一条命令。接管要同时撤销代理输入租约，防止双方同时打字；继续时重新采集页面和焦点，不重放旧坐标。取消停止任务并说明已经发生的动作，不承诺撤回已发送内容或取消外部订单。紧急停止快捷键由宿主机处理，不依赖 guest 或模型响应。

手动输入只在明确聚焦 VM 画面后进入 guest；聊天输入始终留在宿主机。系统快捷键捕获、中文输入法、剪贴板与拖放需要独立测试，避免用户以为在聊天却把敏感文字输入网页。用户开始操作时可自动转入接管状态，但不自动恢复。

## 05  系统架构与集成选择

### 宿主机是控制面 guest 是执行面

| 位置 | 组件 | 责任与边界 |
| --- | --- | --- |
| Host | 原生窗口与 VM 管理器 | 展示 VM；配置资源与生命周期；只接收明确的手动键鼠输入 |
| Host | 任务编排器与策略层 | 解析目标、选择观察、审批动作、管理状态与预算；策略不交给模型自行关闭 |
| Host | 模型代理与凭证库 | 处理供应商请求和 Keychain；限制目的地；记录用量但不记录秘密 |
| Host | 任务与产物存储 | 持久化事件、授权摘要、文件清单和验证结果；负责导入导出 |
| 边界 | 认证的 guest bridge | 只开放命名操作和文件交换；绑定 VM 身份、任务、控制租约与协议版本 |
| Guest | Cua Driver 与桌面会话 | 在已登录的图形会话中读取 UI、截屏和执行输入；持有 guest TCC 权限 |
| Guest | 浏览器与用户应用 | 执行实际任务；网页和文档内容均作为不可信输入 |

主路径为：聊天目标进入宿主机编排器，经过策略校验，由 bridge 调用 guest 驱动；观察和动作结果返回宿主机，必要信息送入模型，再验证结果。模型不直接访问宿主机文件系统或任意命令行。VM 画面由显示路径提供，代理观察由 guest 驱动提供，两条路径分别做新鲜度检查。

### Lume 与直接使用 VZ 的选择

| 方案 | 优势 | 待验证成本与采用条件 |
| --- | --- | --- |
| 直接集成 VZ | 单进程或清晰隔离的 VM 所有权；原生嵌入显示与生命周期可控 | 自己实现安装、配置、恢复、诊断与迁移。适合最终原生体验，但先估算维护成本 |
| 复用 Lume | 复用现有 VM 创建与管理经验；较快验证 guest 自动化 | CLI 或服务持有的 VM 不能假设直接绑定到本应用 VZ view；要验证库化、源码复用或显示桥接方案 |
| 外部窗口原型 | 实现最快，可验证模型到 guest 驱动链路 | 只作为实验工装；不满足单窗口双栏体验的产品验收 |

建议先并行做小规模技术验证，再固定一条发布路径。若 Lume 嵌入要求长期维护大幅分叉，优先直接集成 VZ，同时参考或复用许可允许的管理实现。无论选择哪条路径，VM 配置、磁盘、辅助存储、硬件模型与机器标识应由同一生命周期管理器一致维护。[S1][S4]

### 驱动适配层

首选 Cua Driver 作为 guest 执行器，通过自有 DriverAdapter 封装 observe、act、health、cancel 和 capabilities。Peekaboo 作为后续替代适配器评估，不列为首版必装依赖。更换驱动不应改变任务数据库、审批逻辑或 UI 状态机；具体能力以锁定版本验证结果为准。[S6][S13]

## 06  代理循环与桌面就绪

### 每一步都以可检查的状态为基础

1. 接收目标并界定完成条件：预期文件、目的地、范围、预算、必须询问的事项；缺少关键条件时先问用户。
2. 检查执行环境：确认 VM 身份、会话未锁定、driver 版本、必要权限、网络和模型能力。
3. 按任务选择最小充分观察：优先可验证的结构化信息，必要时附截图，避免每步传完整桌面。
4. 生成一个有明确目标的动作：指定应用或窗口、关联观察版本，并定义预期变化。批量操作只允许在可验证且低风险的边界内。
5. 在模型外执行策略校验：验证工具白名单、控制租约、目标对象、授权范围和费用限制；需要用户确认则暂停。
6. 执行后重新观察：检查实际变化及副作用。没有预期变化时先诊断焦点、弹窗、页面更新或权限，不盲目重复。
7. 记录结果并决定继续、等待、修复或结束：完成必须有证据，失败保留已完成部分和恢复建议。
### 观察选择与降级顺序

| 观察方式 | 适合场景 | 必要限制 |
| --- | --- | --- |
| AX 无障碍树 | 原生控件、应用窗口、可访问的浏览器界面 | 元素标识和文本可能过期或不完整；执行前确认窗口与新鲜度 |
| 浏览器语义快照 | 已支持浏览器中的网页阅读、表单与标签页 | 需验证浏览器接入方式及权限；只操作用户授权的 profile 和页面 |
| 截图与视觉定位 | 画布、定制控件、AX 缺失、布局歧义 | 使用新截图；验证缩放、分辨率、坐标空间；不对不可见区域猜点击 |
| 文件或结果检查 | 导出文件、下载、应用已保存的结果 | 检查存在性、大小、内容及可打开性；不能用“按钮点过”代替完成 |

不要把“AX 优先”写成永远优先。网页语义、AX 和视觉可能互相矛盾；遇到重要动作或目标歧义时交叉检查。模型需要视觉能力，接口返回 JSON 并不足以证明具备可靠的桌面控制能力。[S8][S9]

### SSH 可用不等于桌面可用

就绪探针应至少包括：guest 已启动；有目标用户的 Aqua 图形会话；桌面未锁；app-owned daemon 存活；权限满足；获得非空且符合当前画面的截图；在受控测试应用进行一次无害输入并验证。每次重启、解锁、驱动升级或权限变化后重跑必要探针。[S6][S7]

如果只有 SSH 能连通而 UI 不可操作，状态显示“等待桌面登录或权限”，不偷偷切到宿主机点击。建立动作超时、同一失败次数上限和总任务预算；恢复路径应有原因，例如重新观察、重启驱动或请求人工处理，而非无限重试。

## 07  安全边界与文件交换

### 有边界的主客机通信

MVP 可先验证 SSH stdio 到 guest 驱动的路径，随后包成用户不可见的受限 bridge。每 VM 独立身份，固定 host key；禁止默认口令、SSH agent 转发和不必要的端口转发。仅接收白名单 RPC，避免把字符串拼成任意 shell 命令。若改用本地 socket 或其他传输，仍需身份认证与同等边界验证。[S6]

建议命令信封包含协议版本、VM ID、job ID、唯一 command ID、控制租约、观察版本、截止时间和操作参数；响应包含结果、错误类别及验证证据引用。限制消息大小、文件体积、频率与并发。迟到响应不能改变已取消任务；重复请求须可识别，断线后不能默认重发有外部副作用的动作。以上为拟议协议，需通过集成与安全测试。

### 审批应绑定具体动作

普通只读浏览和已授权的可逆编辑可连续执行；发送、发布、上传、付款、删除、安装软件及改变安全设置应按动作风险设置确认或人工接管。批准包含目标、内容摘要、金额或影响、有效期与动作标识；关键字段或页面变化后重新确认。网页中的“用户已批准”文字不能成为授权。

账户口令、支付与敏感认证使用独立手动接管流程。接管时暂停模型观察和截屏上传，界面明确提示何时恢复。掩码和自动识别只能降低风险，不能保证截图中所有秘密都被发现；对隐私要求高的步骤，宁可完全停止采集。

### 网页与文档中的指令一律视为数据

- 用户目标与外部内容分区保存；页面文本、下载文件、工具结果不能修改系统策略或扩大目标范围
- 限制工具、网络目的地与可读写目录；请求把文件或凭证发送到新地址时，由策略层核对任务与授权
- 重要操作展示真实域名、对象与影响，不能只展示模型生成的可信叙述；对隐藏文本、跨站跳转和伪装系统提示做对抗测试
- 提示词约束不能单独抵御注入；隔离、最小权限、执行前校验和人工确认共同限制后果
### 文件导入导出与网络

导入由用户选择文件，复制到 guest 的任务输入目录并记录清单；默认只读原始输入。导出从任务输出目录选取文件，经大小、类型、文件名和路径校验，再由用户选择宿主目标。拒绝路径穿越、符号链接逃逸和覆盖敏感路径；默认不共享整个主目录，也不自动同步剪贴板。

VM 使用受控网络配置。NAT 不是完整安全隔离：要测试并限制 guest 对宿主服务、局域网和管理端口的访问；必要例外须可解释。guest 上网和宿主模型请求是两条不同的数据出口，隐私页面分别说明。日志默认不收完整截图与网页正文，诊断上传由用户主动选择并预览；保留期限和清除功能应可配置。

## 08  持久任务与恢复机制

### 任务状态不依赖对话上下文

在宿主机持久化任务目标、完成条件、模型与驱动版本、预算、步骤、输入输出清单、等待原因、授权记录和外部动作账本。建议采用事务型本地存储与追加事件日志。聊天展示从这些状态派生；不能仅根据最后一句模型输出判断任务成功。

每个步骤至少记录 planned、dispatched、observed、verified 或 uncertain。状态落盘后才派发动作，确认结果后才推进。应用崩溃后先进入恢复检查，获取新观察，核对外部状态，再决定继续。无法证明某个提交是否成功时标为 uncertain，不通过重试消除不确定性。

### 持续运行的三个层级

MVP：一个用户可见的活动任务，支持短暂等待、限流退避、暂停和安全恢复。第二阶段：增加下载或远程任务的有界等待、任务队列和小时级运行。第三阶段：在明确的运行时间、费用、网站和动作授权下再考虑定时与无人值守。等待必须有成功、失败、用户取消或明确截止条件。

宿主机睡眠、关机、掉电或用户退出都会影响本地运行。用户可选择在接电时防止空闲睡眠，但不得承诺合盖后继续。进入睡眠前尽力落盘和停止派发；唤醒后检查时钟跳变、网络、guest 会话及待确认动作。不要把“任务仍显示执行中”当作实际进度。

### 区分恢复运行与恢复备份

运行状态保存用于回到同一次 VM 执行；Apple 要求先暂停，并且恢复时配置一致。磁盘与辅助存储等外部资源需要另行一致保存。保存的运行状态受 Mac 和用户账户限制，格式兼容性变化可能需要舍弃内存状态并冷启动。[S10]

首版优先提供关闭 guest 后的备份点：保存磁盘、辅助存储、硬件模型、机器标识、配置和组件版本的匹配集合；校验完整性并显示空间成本。恢复前保留当前状态，明确是恢复本机环境，不是撤销互联网操作。热备份、迁移到另一台 Mac 或任意跨版本恢复必须单独验证。

### 外部副作用不能回滚

发送的邮件、提交的表单、上传的文件、产生的费用及网站上的修改，不会随着 VM 备份恢复而撤销。外部动作账本应尽量保留在宿主机且独立于 guest 备份；恢复旧 VM 后先核对该账本，再连接外部服务，避免重复发送或重复付款。

### 运行成本与健康状态

显示任务累计模型用量、等待时长和剩余预算；预算耗尽先暂停。监测 guest 心跳、最近画面时间、磁盘余量、驱动健康及持续失败。低磁盘时停止非必要下载；崩溃恢复、清理和升级不得自动删除用户产物。遥测和支持诊断的默认设置需清楚披露。

## 09  测试矩阵与验收目标

以下数字均为建议验收目标，尚未实测。发布前锁定硬件、系统 build、网络条件、模型及驱动版本；同时记录成功率、尾延迟、失败原因与人工介入次数，不能只展示最佳演示。

### 建议的 MVP 验收指标

| 指标 | 建议门槛 | 测量办法 |
| --- | --- | --- |
| 首次可用 | 10 次干净安装中至少 9 次完成；完成必要授权后 2 分钟内通过就绪检查 | 真实用户路径；安装下载耗时分项披露，不计入 2 分钟 |
| 基本任务 | 30 个固定任务，每项 3 次；独立验收通过率至少 85% | 按文件内容或外部状态评分；模型自报不计成功 |
| 安全审批 | 测试集内需要确认的操作 100% 被拦截；无批准不得执行 | 覆盖目标变化、过期批准、注入诱导、取消后迟到响应 |
| 暂停与接管 | 点击后 1 秒内停止派发新动作；任何时刻只有一个输入持有者 | 测客户端调度日志；在途动作单列，不承诺撤销 |
| 恢复可靠性 | 50 次故障注入无已确认产物丢失；不重复执行非幂等动作 | 在派发前后、提交期间、落盘期间杀进程与断网 |
| 显示与观察 | 受控环境中画面新鲜度 P95 小于 500 ms；普通观察 P95 小于 2 s | 固定分辨率与资源；模型推理延迟单列 |
| 密钥与隔离 | 诊断包及日志明文 Key 检出为 0；禁止目录和端口访问测试全部通过 | 使用测试秘密、抓包与路径逃逸用例，不使用真实凭证 |

### 必须覆盖的实际场景

- 平台与输入：较早及较新 Apple Silicon；主客系统组合；不同分辨率与缩放；中文输入法、英文键盘、菜单和系统快捷键
- 授权与会话：首次允许、拒绝、撤销、驱动升级、guest 重启、锁屏、注销、只有 SSH 可用、空白或过期截图
- 任务质量：页面改版、弹窗遮挡、下载未结束、另存为冲突、输入焦点错误、网页无 AX、需要视觉定位、结果文件打不开
- 异常与对抗：模型 401/429/超时；VPN 和断网；空间不足；合盖睡眠；host 崩溃；提示注入、假审批、越权文件导出、命令重复与乱序
测试分层：单元测试覆盖状态机、策略、预算和路径校验；合同测试覆盖驱动适配器与 RPC；真实 VM 端到端测试覆盖 UI 与权限；人工探索测试覆盖首次体验与接管。每个发布候选保留脱敏失败轨迹和版本清单，便于复现。

## 10  分阶段实施与发布闸门

采用证据驱动的阶段闸门，不在尚未验证的集成上承诺固定交付日期。每阶段通过后再扩大用户范围；任何关键许可或安全问题未闭环，应停止对外发布而非只增加免责声明。

| 阶段 | 必须交付的结果 | 通过条件 |
| --- | --- | --- |
| G0 立项 | 目标用户与使用范围；Apple 和依赖许可清单；发行方式候选 | 商业用途、OS 安装与分发边界获得可采用的结论；暂用名称完成初步排查 |
| G1 技术闭环 | 嵌入 guest 画面；聊天发指令；guest 驱动执行；文件导出 | 在真实 Mac 连续完成观察、输入、保存、核验；明确选用 Lume 或直接 VZ |
| G2 可用产品 | 首次引导、密钥配置、任务状态、权限检查、暂停接管 | 非开发者无需终端完成设置；缺权限与失败能定位；基础任务集达到目标 |
| G3 受控试用 | 有限应用与模型支持；更新、日志、异常恢复及安全策略 | 通过安全和故障测试；用户数据清理可验；严重缺陷归零且已知限制公开 |
| G4 持续任务 | 耐久状态、外部动作账本、长时间等待、预算与睡眠恢复 | 达到延长运行测试目标；不重复提交；明确运行条件与用户授权范围 |
| G5 扩展发布 | 扩大应用矩阵、可替换驱动、其他模型或资源档位 | 新增能力分别通过回归；升级不破坏授权身份和任务恢复 |

### 优先处理的风险

许可风险：Apple SLA 的虚拟实例用途限制不能从 MIT 开源许可中推导解决方案。一般商业办公、预装镜像分发和云化需分别确认；在确认前不要把它们写成已支持范围。[S3]

集成风险：Lume 的 VM 生命周期与原生嵌入显示是否能干净复用，需要实测。若必须跨进程显示或维护分叉，应比较性能、输入延迟、更新成本和稳定性，而不只看第一周开发速度。

稳定性风险：驱动、OS、浏览器、模型任何一层更新都可能改变结果。采用版本锁定、小范围更新与可回退发布；能力变化必须重新跑任务集。

安全风险：VM 只缩小影响范围，无法使已登录网站内的误操作无害。用最小共享、策略校验、批准与审计限制后果；保留清晰的人工处理出口。

依赖风险：Cua 仓库默认 MIT，Lume 和 Driver 主体可据具体路径审查复用，但可选感知模型及其他包可能适用独立许可。MVP 不主动引入未经审查的 AGPL 组件或权重；每次发布生成依赖与版权告知清单。[S12]

建议责任分工：产品负责任务与验收定义；macOS 工程负责 VZ 与安装体验；代理工程负责模型和驱动协议；安全与法务负责边界与许可评审。人员规模和投入在 G1 结论后估算。

## 11  演示脚本与待决事项

### 用真实结果演示核心价值

建议主视频为 3—5 分钟，使用已经完成安装的环境。首次安装另录短视频，明确标出系统下载与人工授权耗时。主演示固定一个可复现目标，保留真实等待；如剪辑或加速，画面注明。不要把预制文件冒充代理产出。

| 片段 | 画面与操作 | 证明什么 |
| --- | --- | --- |
| 开场 | 单窗口左侧 macOS guest，右侧 host 聊天；展示当前模型与 VM 就绪 | 产品形态清晰，运行的是独立 guest |
| 发起任务 | 用户说“打开这两个公开文档，整理三点要点，保存为一份笔记并导出给我” | 用户用目标语言，而非逐步点按脚本 |
| 实际执行 | 代理在 Safari 阅读指定页面，在 TextEdit 写入要点与来源，保存文件 | 能够观察、跨应用操作并产生可检查输出 |
| 人工接管 | 用户暂停，修改文件标题，然后点继续；代理重新观察 | 控制权可交还，不会接着点击旧位置 |
| 交付与复查 | 聊天展示结果与导出入口；用户在宿主机打开文件，核对标题、三点要点和链接 | 交付是真实可读产物，完成经过验证 |
| 收尾 | 展示任务记录、用量和受支持范围；说明本地 Mac 必须保持可运行 | 能力边界透明，不把演示等同于全应用支持 |

演示素材建议使用 Apple Virtualization 与 Cua 的公开文档，事先确定 URL 和期望字段。发生阻塞时展示真实的恢复或失败提示；保留完整未剪辑录屏作为内部验收证据。视频不展示个人登录、真实 API Key 或无关的桌面内容。

### 下一轮需要定下的五件事

1. 首批用户与合法用途：先面向个人非商业使用、开发测试，还是必须覆盖商业办公？这会改变发布门槛。
2. 虚拟机实现：G1 以同一验收任务对比直接 VZ 与 Lume 复用，确认显示、生命周期与后续维护成本。

### 名称与立项边界

Chat Computer 仅为暂定名称。公开同名项目的存在意味着仍需做商标、域名与分发平台名称排查；用户名返回 404 不能证明可注册。本方案完成后可以据此拆分工程任务和原型验收，但不等于已经授权开发、注册账户或发布产品。
