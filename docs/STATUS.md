# 现状与规划

更新于 2026-10-02，对应版本 **0.1.0**（预览版，[GitHub Release](https://github.com/chatcomputer/chatcomputer/releases/tag/v0.1.0)）。

背景和长期计划见 [ROADMAP.md](ROADMAP.md)，界面与架构设计见 [DESIGN.md](DESIGN.md)，逐项清单见 [../TODO.md](../TODO.md)。

---

## 1. 一句话现状

在一台 macOS 27 的 Mac 上，App 能从零装好一台 macOS 虚拟机。用户在右侧聊天框里描述任务，模型在左侧虚拟机里看屏幕、点鼠标、打字完成任务；产出文件经宿主校验后交付。

整个流程已用 DeepSeek 在真实虚拟机上端到端跑通。App 已签名、公证，并以 GitHub Release 发布。

## 2. 已经能做什么

### 2.1 首次引导（6 步，全部实测通过）

| 步骤 | 做法 | 实测 |
|---|---|---|
| 1. 安装 macOS | 下载恢复镜像（约 26 GB）后安装；苹果的镜像目录失败时改用苹果 CDN；也可选本地 `.ipsw` | 安装 173 秒，磁盘约 29 GB |
| 2. 创建账户 | `VZMacGuestProvisioningOptions` 自动建号、自动登录，不经过设置助理 | 开机即到桌面 |
| 3. 安装 agent | 通过 SSH 装好 guest 里的 agent，装完关闭 SSH | 开机后约 14 秒 |
| 4. 授权 | 宿主级控制：读取虚拟机画面、本机文字识别找到开关并打开，自动输入钥匙串里的 guest 密码；用户无需输入 | 两项权限自动完成 |
| 5. 保存初始状态 | agent 从虚拟机内部干净关机，冻结磁盘为 base + overlay | 关机约 66 秒 |
| 6. 连接模型 | 选厂商、协议、模型，填 Key，点「Save and test」 | DeepSeek 通过 |

### 2.2 执行任务

用 DeepSeek（`deepseek-flash`）在真实虚拟机上实测：

| 任务 | 结果 | 用时 | 输入 token |
|---|---|---|---|
| 打开浏览器 | 完成 | 35 秒 | 1.4 万 |
| 打开 Safari 访问 apple.com，说出首页大标题 | 完成，回答正确 | 55 秒 | 4.5 万 |
| 打开浏览器搜索“macOS 27 发布日期”，汇报结果 | 完成，区分了官方来源与 AI 摘要 | 76 秒 | 8 万 |
| 在 TextEdit 写一行字，存为 outbox 里的 hello.txt（3 次） | 3/3 完成，文件经宿主校验 | 127–448 秒 | 23 万–110 万 |

模拟桌面上的三个安全场景（正常完成、需要审批的发邮件、屏幕上的提示注入）在两种协议下都通过。

### 2.3 产品能力一览

- **界面**：左侧虚拟机画面固定 16:10、无边距，右侧 380 pt 的面板。引导和主界面共用同一尺寸，窗口大小不变。状态显示在窗口副标题里。
- **控制**：可暂停、接管、取消。接管只认真实的点击或按键，并在聊天里说明原因。
- **模型**：
  - 支持 OpenAI 兼容（Chat Completions）和 Anthropic 兼容（Messages）两种协议。
  - 内置 10 个厂商：Anthropic、OpenAI、Google Gemini、DeepSeek、xAI、Mistral、通义千问、Kimi、智谱 GLM、豆包，每家至少 3 个模型，于 2026-10-01 对照官方文档核实；另可填自定义地址。
  - Key 按厂商存入钥匙串。
- **Agent 循环**：
  - 所有限制在模型之外执行，包括任务阶段、输入租约和预算。
  - 完成必须有证据：`report_result` 列出的文件由宿主逐个校验。
  - 每轮操作后自动附上新截图，非 Claude 端点只保留最近 3 张截图。
  - 剩 10 轮时提醒模型收尾。
- **安全**：
  - API Key 只在宿主。
  - 虚拟机经 vsock 通信，配对令牌保护连接。
  - guest 拒绝没有租约的输入。
  - 屏幕文字视为数据而非指令；不可逆操作前必须调用 `ask_user`。
- **发布**：Developer ID 签名、hardened runtime、Apple 公证、装订；一条命令完成（`scripts/release.sh`）。
- **更新 agent**：agent 能从共享目录自我更新，但只接受同一团队签名的新版本。
- **快照**：
  - 运行中拍快照会连内存一起保存，恢复后打开的应用和窗口原样回来；关机状态下只保存磁盘。
  - 文件用 APFS 克隆，几乎不占额外空间，任意快照都能单独恢复或删除；快照之间按来源形成分支。
  - 恢复前可以先把当前状态存成快照，方便撤销。
  - 引导完成时自动记下受保护的「Freshly set up」，恢复它就是重置电脑；老虚拟机在第一次操作快照时补上。
  - 恢复按日志执行：中途崩溃的话，下次启动时要么完成、要么回滚。
  - 入口：聊天面板底部的时钟按钮、菜单「Machine」（⌥⌘S 拍快照，⇧⌘S 打开列表）。

## 3. 测试体系

| 层 | 内容 | 命令 |
|---|---|---|
| L0 单元测试 | 57 个：协议、状态机、租约、预算、导出校验、两种协议的转换、厂商目录、KeyMap、DHCP 租约、agent 循环、快照（含恢复中断的回滚） | `swift test` |
| L1 构建 | 两个 App 与 entitlement 检查 | `scripts/test-mac.sh` |
| L2 宿主 API 自检 | DiskImageKit 分层与重置、vmnet | `scripts/harness.sh vm selftest` |
| L3 真实模型 + 模拟桌面 | notes / approval / injection 三个场景 | `scripts/harness.sh live-loop --scenario …` |
| L4 真实虚拟机 | 安装、启动、vsock、截图、挂起恢复、关机；快照（`vm snapshot-test`）；输入可靠性（`--input-test`，13/13）；经 agent 手动操作（`--agent-console`） | `scripts/harness.sh vm up …` |
| L5 发布 | 签名、公证、Gatekeeper | `scripts/release.sh` |

开发用环境变量（正常使用时都不设置）：

- `CC_GUEST_PASSWORD`：首次开机时使用已知的 guest 密码，至少 4 位
- `CC_AUTO_ONBOARD=1`：自动依次执行引导各步
- `CC_DEV_MODEL` / `CC_DEV_API_KEY`：直接配置模型，格式如 `deepseek:openAI:deepseek-flash`
- `CC_DEV_TASK`：虚拟机就绪后自动提交这条任务
- `CC_DEV_LOG`：把 agent 循环的每条更新写到文件
- `CC_DEV_HARNESS_SECRETS=1`：把虚拟机密钥交给 `cc-harness`，不触发钥匙串弹窗

## 4. 已知问题与限制

1. **任务成本不稳定**：同一任务快的 2 分钟、约 25 万 token，慢的 7.5 分钟、约 110 万 token。模型有时会反复确认已经完成的步骤。
2. **只有 DeepSeek 做过真实任务**：Claude 和其他厂商只测到协议层，没有 Key 做真实任务。Claude 的 `computer_toolset_20260801` 请求还未真正发出过。
3. **任务不持久**：任务存在内存里，退出 App 即丢失。
4. **剪贴板不共享**：宿主和虚拟机之间还不能复制粘贴。
5. **一次无法复现的接管**：曾有一次任务进行中切换成「你在控制」，原因未查明。之后改为只认点击和按键，并在聊天里写明原因，此后没有再出现。
6. **尚未验证**：
   - 中文输入法与系统快捷键（P2）
   - 带 overlay 的磁盘 IO 性能（P4；带 overlay 启动已在日常使用和快照测试中验证）
   - guest 能否访问宿主上的本地服务（P5）
   - guest 侧的只读与符号链接逃逸（P7）
7. **许可**：macOS 软件许可协议对虚拟机用途有限制，确认前只面向个人非商业与开发测试。

## 5. 规划

按优先级排列。每项完成的标准是：能演示，且有对应的测试。

### 近期（0.2）

1. **新电脑实测 0.1.0**：从下载 Release 到完成第一个任务，记录卡住的地方并修复。
2. **用 Claude 跑真实任务**：验证 `computer_toolset_20260801` 的请求和返回，与 DeepSeek 对比完成率和成本。
3. **固定任务回归集**：先做 10 个任务，包括浏览器、文本编辑、文件整理和需要审批的操作。每个模型每个任务跑 3 次，记录完成率、用时和 token，作为改动前后的对照。
4. **降低成本**：
   - 让模型少做重复确认（提示词和回合提醒）。
   - Claude 改用服务端清理旧的 tool result，而不是在客户端删截图。
   - 评估「每轮自动截图」对 token 的影响。
5. **任务持久化**：SQLite 存储任务和事件日志；App 重启后进入「待检查」，重新截图再继续。
6. **流式输出**：模型回复改为流式，聊天里实时显示进度。

### 中期（0.3–M3）

- **审批卡片**：`ask_user` 显示目标和具体内容，提供批准、拒绝按钮。
- **任务前自动快照**：高风险任务前自动拍快照，失败可一键回退（快照与重置已完成，见 §2.3）。
- **剪贴板共享**，以及把文件拖进 inbox。
- **挂起恢复**：退出 App 时挂起虚拟机，下次启动直接恢复。
- **诊断包**：脱敏，导出前可预览。
- **更丰富的驱动**：辅助功能树和浏览器语义快照，减少只靠截图坐标操作。
- **CI**：Linux runner 跑 L0；自托管 Apple 芯片 runner 跑 L1–L3。
- **外部编程 agent 接入**：提供本地 MCP 服务，让 Claude Code、Codex 等通过同一租约操作虚拟机。

### 长期（M4）

外部动作账本、长时间等待、睡眠与唤醒恢复、overlay 合并维护。
